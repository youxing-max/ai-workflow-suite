# 第一站 Brainstorm · 需求澄清

核心问题：**我们理解的是同一个问题吗？**（控制目标不确定性）

## 翻车现场：一句话需求，五分钟 PR

你说一句需求，AI 立刻开写。它不是在偷懒，**是在替你补全**。收到"给贵族体系增加权益展示"，Agent 很可能顺手假设：

- 所有终端展示相同内容；
- 本人和他人看到的礼物墙相同；
- 没有配置时使用默认展示；
- 新字段只需新增，不用考虑旧版本；
- "隐藏"只代表前端不渲染。

每项单看都不离谱，但每项都会改变产品行为或系统风险。等 PR 打开，你才发现它回答的根本不是你问的那个问题。

## 方法

**事实与决策分工**（grilling 源码用强调标出 fact / decisions，划的是责任线）：

- 能从仓库查到的**事实**（受影响模块、已有约定、需求歧义）→ AI 先查，不把检索推给人；
- 会产生业务后果的**取舍**（业务目标、风险、兼容成本、不做什么）→ 必须找到具体的人拍板。AI 整理选项、给推荐答案，不能替团队默认。

**沿决策树访谈**：按依赖顺序走每个分支，防"聊了一小时、关键分支没碰到"的伪对齐；每个问题带推荐答案，人只需确认或否决；**没等到答案就是显式状态**——流程停在原地，不默认通过（无人值守模式见 SKILL.md，改为写入待确认清单）。

**产出可检查的业务规则**：澄清的产物不是"聊过了"，而是产品/开发/测试能共同确认的规则。案例真实 PRD 浓缩的五条：

> 1. 收礼、送礼礼物墙的可见范围分别设置，档位：全部展示（默认）/ 仅近 1 年 / 仅近半年 / 仅近 3 个月 / 不展示。
> 2. 本人查看始终看到完整数据，被隐藏部分用分界线和锁头标记；他人视角任何情况下不出现锁头。
> 3. 他人查看只能获得可见范围内的礼物，范围外数据**不进入接口响应**；数量和冠名按**累计值**展示，不受时间过滤影响。
> 4. 该设置是付费权益，不满足等级的用户没有设置入口，操作时引导开通。
> 5. 旧版本终端无法隐藏等级行时降级展示：缺省图 + 名称固定"礼物墙" + 点亮数量显示"未点亮"。

第 3 条"数量和冠名按累计值展示"是典型的反直觉细节：不写下来，实现的人大概率按直觉做成"全部按半年算"。

**典型待澄清清单**（跨端需求通用，指澄清阶段要问清的事）：是否所有终端/玩法一致生效？本人与他人视角是否区分？无配置时默认行为？旧版本遇到新配置怎么办？"隐藏"的语义边界（前端不渲染 vs 数据不下发）？哪些终端必须同批上线？

## 本地 skill

| skill | 调用 | 用途 |
|---|---|---|
| grilling | 模型可调用，直接加载 | 决策树访谈直到 frontier（前提已就绪、当前可问的问题集合）清空；用户确认共同理解前不执行 |
| grill-me / grill-with-docs | 用户触发 | 同款拷问；with-docs 版边聊边产出 ADR 与词汇表 |
| openspec-explore | 模型可调用 | OpenSpec 探索模式：先聊透范围边界，默认不产生正式变更，经确认后可在确认范围内创建变更材料 |
| to-questionnaire | 用户触发 | 把答不了的决策打包成问卷，交给能拍板的人 |

> 访谈形态（本套件规定）：grilling 采用整轮 frontier 提问——编号、每题带推荐答案、显式等待回答后再进下一轮，"问多答少"的风险由这三件事化解。执行协议以本地安装的 grilling skill 为准；方法论原则（决策树访谈 / 事实决策分工 / 确认前不执行）由本套件规定，不因工具版本变化。

## Artifact 与 Gate

- **Artifact**：决策记录 / 业务规则清单（共同理解）。
- **Gate**：关键取舍已确认；没确认，实现不开始（无人值守见 SKILL.md「无人值守模式」）。更强的做法是硬门禁：批准设计前禁止调用任何实现类 skill（无人值守见 SKILL.md「无人值守模式」）。

## 出口信号

- 技术假设无法确认 → 先 prototype 验证，再回需求侧澄清；不要在没验证的假设上继续往下设计；
- 需求对齐 → 进入 [Stage 2 Design](stage-2-design.md)："要什么"清楚了，"放进系统哪个位置"还没定。

## 坑点清单

- [ ] 一次裸抛多个问题（无编号、无推荐答案、无等待回答），人只答了最后两个，前几个被默认通过；
- [ ] 伪对齐：聊了一小时，关键分支没碰到；
- [ ] 规则写成形容词（"做好权限控制"）而不是可检查断言；
- [ ] 反直觉细节没写下来（如累计值不受过滤影响）；
- [ ] AI 替人拍板了业务取舍；
- [ ] 聊完顺手开写，跳过"确认共同理解"这一步。
