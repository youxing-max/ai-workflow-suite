# 第二站 Design · 方案设计

核心问题：**需求怎样进入现有系统？这项责任应该放在哪里？**（控制系统边界不确定性）

## 翻车现场：每层都在判断"是不是本人"

"他人查看礼物墙"涉及两个身份：墙属于谁、当前查看者是谁。如果每层都接收两个用户 ID 各自判断：HTTP 层判一次、领域服务再判一次、APP 和 H5 各有一套、某条消息链路拿不到查看者身份只好猜、隐私规则分散到没人说得清哪处是准的。代码都能运行，系统边界已经松了。

因果链：上一站"他人不能获得隐藏数据"这条规则，如果在这里不落到一个确定的位置，**后面每个环节都会用自己的方式重新解释它**。

更安静的翻车：设计只存在于聊天记录里，边界判断随实现散落各层，两个月后没人说得清"为什么这么设计"，新会话接手只能从头考古。

## 方法：三处决策，一个前置

**① 责任归属**：需要完整上下文的关系判断（如本人/他人），放在拥有完整登录信息的请求入口统一做；下游只接收明确语义（SELF / OTHER），不再反复猜"谁在看"；过滤只发生在一处。规则只有一个出处，改一处就全改对。

**② 跨端资源隔离**：APP 与 PC 动画格式不同时，不为复用字段互相覆盖——多几个字段通常比跨端语义污染便宜。真实决策样例：新增"PC 端动画资源"字段，填了直接读、没填由服务端自动从 pag/svga 转 webp；存量资源用独立定时 Job 离线转换写回。**新字段、默认值、兜底转换，三件事一次写清**；存量处理另列待确认项，不混进主流程。表情包权限不散落成 if-else，收进独立权限管理器，锁态和文案走配置。

**③ 新旧兼容用降级**：旧版 APP 的个人主页无法做到"隐藏等级整行"时，决策是降级而不是硬撑（缺省图 + 固定文案"礼物墙" + "未点亮"）；PC 表情包同样按版本处理——低于某个版本的客户端保留"可以查看、无法发送"，新版本才能发送。降级决策不写进设计材料 → 各端按自己理解猜 → 同一用户在不同设备看到两种结果，隐私功能最怕这种漂移。兼容逻辑不会自动正确，它只是把设计阶段的降级决策逐条兑现：协议新字段一律判空，旧版服务不下发就走原逻辑。

**测试接缝（seams）前置**（to-spec 第 2 步，前置进 Design）：写方案前先勾出打算在哪些接缝上验证——优先复用现有接缝、用尽可能高的层级、越少越好（理想数量是 1），并与用户确认符合预期。案例中"他人查看礼物墙"的接缝选在**接口响应**而不是页面渲染——这个选择直接决定第五站能否抓住"前端不渲染但数据照返"。

设计材料不求长，五项够用：**方案边界和数据流、接口变化、兼容与降级策略、测试接缝、明确不做什么**。

## 本地 skill

| skill | 调用 | 用途 |
|---|---|---|
| to-spec | 用户触发（/to-spec） | 只综合不访谈：把讨论结果落成七节 Spec，发布到 issue tracker 打 ready-for-agent 标签 |
| codebase-design | 模型可调用 | 深模块词汇：接缝放哪层、接口怎么设计 |
| domain-modeling | 模型可调用 | 领域词汇表与 ADR：保证 Spec 用词和代码用词是同一套 |
| prototype | 模型可调用 | 一次性原型验证状态模型 / 交互假设 |
| openspec-propose / openspec-ff-change | 模型可调用 | 把变更落成 openspec/changes/ 合同（proposal + spec，复杂变更加 design + tasks），Spec 用 SHALL/MUST + Scenario 写成可检查场景 |

**to-spec 七节模板**：Problem Statement / Solution / User Stories / Implementation Decisions / **Testing Decisions** / **Out of Scope** / Further Notes。Testing Decisions 与 Out of Scope 独立成节因为最常被漏：漏 Testing Decisions，Execute 没有观察点；漏 Out of Scope，Agent 会把顺手能做的都塞进范围。写 Spec 前先读仓库和已有 ADR——新设计与旧 ADR 冲突时，要么改方案，要么显式推翻旧决策，不能假装它不存在。Spec 的终点不是一份文档，而是任务系统里一张能被 Agent 直接领走的工单。to-spec 为什么禁止模型自动触发：落 Spec 是"落锤"动作，落锤权在人手里——不允许模型觉得"聊得差不多了"就自行固化 Spec，这与 Design 的 Gate 是同一件事的两面。

## Artifact 与 Gate

- **Artifact**：Spec、设计文档、必要的 ADR。
- **Gate**：边界和测试入口已确认；没有成型的 Spec，不进入拆任务（无人值守见 SKILL.md「无人值守模式」）。

## 出口信号

- 发现需求矛盾 → 回 [Stage 1 Brainstorm](stage-1-brainstorm.md)；
- 方案落定 → [Stage 3 Plan](stage-3-plan.md)：好设计不等于能一次塞给 Agent 执行的任务清单。

## 坑点清单

- [ ] 最危险的问题不报错：编译通过、局部测试绿、行为错误；
- [ ] "隐藏"只做成前端不渲染，接口照返数据；
- [ ] 身份判断散落各层，某条链路拿不到身份只好猜；
- [ ] 跨端复用字段互相覆盖，一个端改资源另一个端展示异常；
- [ ] 新设计与既有 ADR 冲突，既不改方案也不显式推翻；
- [ ] Spec 术语和代码术语两套词；
- [ ] 测试接缝等代码写完再补（接缝是设计的一部分）；
- [ ] 设计只留在聊天记录，没落成仓库里的材料。
